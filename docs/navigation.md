# 导航状态：一次设计，而不是逐页打补丁

> 状态：**设计稿**（先定做法，再动代码）。相关：前端说明、AGENTS §17（界面改动先渲染）、§18（前端边界）。

## 1. 问题不是「返回坏了」，是「我在哪」没有唯一答案

今天的导航状态散在三处，而且**三处都不完全可靠**：

| 存在哪 | 谁在写 | 切页 / 刷新会怎样 |
| --- | --- | --- |
| useNavigation 的 view | 顶栏、各处 setView() | 切页保留，**刷新丢** |
| 各 view 自己的 useState（opened / 选中版本 / 展开的面板） | 各 view | 切页**卸载就丢** |
| location.hash（#room、#slot=wol） | 半套机制 | 只有写了才留 |

后果就是同一类 bug 反复出现，每次都得**逐页适配**：

1. 安装页装完 → 掉回主页（已踩；修法是给战役页单独写 hash）
2. 自制战役页装完 → 掉回主页（同一个病，还没修）
3. 刷新一下 → 无论在哪个战役都被弹回列表
4. 想做深链或浏览器后退 → 没有基础设施

**共同点**：页面被卸载 → 局部 state 归零 → 用户被弹回默认位置。
逐页修是 O(页数)，每加一页就漏一页。

## 2. 候选方案

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A. URL 即状态**（推荐） | 导航状态全进 URL：?view=campaigns&slot=wol，配 navigate() / back() | 切页、刷新、深链、浏览器后退全都要到；代价是要约束「什么该进 URL」 |
| B. 升到 AppState | 各 view 重要的 state 提进全局 | 切页能保留，**刷新还是丢**，没有深链，每个 view 都要改一遍接一遍 |
| C. 只做导航栈 | 记住来路，back() 回去 | 解决「装完回原处」，解决不了「页面内部状态」（战役还开不开着） |
| D. 现状（逐页适配） | 每页自己写 hash、自己记 return | 每加一页漏一页 |

## 3. 推荐：A + 浏览器历史（navigate / back / useViewParams）

三件小东西，加起来约 150 行，替代掉零散的 installReturn 与手写 hash。

代码骨架（types 略）：

    readRoute(): Route                     // 解析 location（含 popstate）
    navigate(patch: Partial<Route>): void   // 合并当前 route 并 pushState
    back(): void                            // history.back()，给「装完 / 返回」用
    useRoute(): Route                       // 订阅 popstate，变化即重渲染

**关键约定（这才是「不再逐页适配」的地方）**：

- **进 URL 的只有「位置」**：哪一页、哪个战役、哪个版本、开没开面板。它们都能从库里重建，所以放 URL 是安全的。
- **不进 URL 的**：输入框草稿、滚动位置、hover、拖到一半的状态 —— 它们瞬态，丢了不构成 bug。
- 一个 view 想记住位置 → **加一个 URL 字段**（一行），而不是加一套自己的持久化（一套就是一个会漏的地方）。

于是那四个 bug 不用逐个修：

- 装完回原处：back()，安装页压根不需要知道「从哪来」。
- 哪个战役开着：?slot=wol —— **战役页与自制战役页共用同一个字段**，因为语义都是「打开了一个东西」。
- 刷新：URL 还在，readRoute() 照样还原。
- 深链：把 URL 发出去就行。

## 4. 迁移（三步，每步都能单独发布）

1. **落地 router**，把 ?view= 与 #room 统一成 ?view=（room 仍要求开发者模式）。
2. **战役页 / 自制战役页**的「打开的是哪一部」迁到 ?slot=，替换掉刚手写的 #slot=wol。
   自制战役用 ?slot=custom 加上 variant 字段 —— 不再出现 custom: 这种拼接（刚踩过：/slot=([a-z]+)/ 会把它读成 custom）。
3. **安装页**去掉 installReturn，onInstalled / onBack 改调 back()。

## 5. 边界与风险

- **别把 URL 当 store**：只放位置，不放数据。放错会让 URL 变长，也让分享链接泄露不该泄露的东西（本地路径绝不进 URL）。
- pushState 会攒历史：页面级跳转用 pushState（能 back），页面内部的选中用 replaceState（不积历史）。
- 顶栏切页也走 navigate()，避免两套写 URL 的代码。
- 与 #room 的兼容：现有截图脚本与调试入口用 hash，迁移期两种都认，最后只留一种。
- 这一轮只改导航、不动观感，所以按 AGENTS §17 不需要出设计稿；但要有「三个页面都能正常进出 + 刷新不丢」的验证。

## 6. 验收（做完立刻能验的四条）

1. 战役页 → 进某个战役 → 刷新 → 还在那个战役里。
2. 战役页 → 进某个战役 → 安装页 → 装完 / 返回 → 回到那个战役（不是列表）。
3. 自制战役页 → 装完 → 回到自制战役页（同一个机制，不再单独适配）。
4. 演示模式里浏览器后退 → 回到上一处。
