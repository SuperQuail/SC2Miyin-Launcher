# v0.1.0a2 —— 启动器能自己更新了

> 预发行版。这一版的主题是**自动更新**与**国内可用性**。

## 这一版加的东西

### 启动器可以基于 GitHub Release 自己更新

设置页新增「更新」面板：检查 → 下载 → 安装并重启，全程不用手动去 Releases 页面找包。

- 检查更新时**按版本号挑最大的**，不是取列表第一个 —— GitHub 是按**创建时间**排序的，
  补发的旧版本会排在前面（参考项目踩过这个坑）。
- 版本号认不出来就**当没有更新**，绝不提示一个错误的"有新版本"。
- 更新包下载后会**校验 SHA-256**（摘要来自 GitHub API）；对不上就删掉重来 ——
  镜像毕竟是第三方，下歪了必须能发现。
- 安装时写一个 `.cmd` 脚本：等主程序让出 exe 的文件锁 → 重试拷贝 → 启动新版本 → 自删。
  Windows 上不能覆盖正在运行的 exe，绿色版软件都是这么做的。

### 国内下载：自动代理 + 镜像竞速

这两条是**独立**的，都会自动生效：

**代理自动选择**（顺序：环境变量 → Windows 系统代理 → 直连）

设置页可以选「自动 / 不使用 / 手动指定」，也会如实显示当前走的是哪条路。

**代理被限流时自动改直连重试** —— 这条是实测出来的：GitHub 的 API 额度按**出口 IP** 算，
国内用的代理往往是共享 IP，额度早被别人用光（实测正好撞上 403，
GitHub 的原话是 `API rate limit exceeded for 58.152.46.170`）。
直连是另一个 IP，多半还有额度，所以值得再试一次。界面会显示「直连（代理被限流）」。

**镜像竞速**（下载时）

release 资产展开成「直连 + 6 个镜像」共 7 个候选，**并发开跑，谁先下完用谁**，
其余的看到别人赢了就立刻放弃、不浪费带宽：

`@text
""                                直连
https://gh.ddlc.top               
https://gh-proxy.com              
https://ghfast.top                
https://cors.isteed.cc            
https://ghproxy.cc                
https://github.akams.cn           
`@

只在下载走 GitHub 的 URL 时启用，可以在设置里关掉。

### 版本号约定改成 `0.1.0a2`

Cargo 只接受 semver，所以：

| 位置 | 写法 |
| --- | --- |
| `Cargo.toml` / `package.json` / `tauri.conf.json` | `0.1.0-alpha.2` |
| 界面显示、git tag、发行说明 | **`0.1.0a2`** |

由 [`version::compact`](../package-format.md) 自动转换，**单一事实来源仍是 `Cargo.toml`**。
版本比较器两种写法都认，而且**等价** —— 否则 `a1` 和 `a2` 会被当成同一版，
永远检测不到更新。

## 修的问题

- **reqwest 会自己读环境变量代理**，导致「关掉代理」「直连重试」这两条路全是假的
  （`proxy = None` 仍被 `HTTPS_PROXY` 拖回代理）。现在显式 `no_proxy()`，
  代理只由启动器统一决定。
- 预发行的判定不再看 tag 里有没有 `-` —— 对外写法 `0.1.0a2` 本来就不带连字符。

## 已知限制

- 更新只替换程序本体，`data/`（导入的战役、补丁）完全不动。
- 镜像列表是内置的；某个镜像挂了会被竞速自动淘汰，但如果**全部**挂掉就只能直连。
- 非 zip 格式的战役包仍依赖系统自带的 `tar.exe`（Windows 10 1803+）。
