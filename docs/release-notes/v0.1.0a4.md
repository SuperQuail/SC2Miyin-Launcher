# v0.1.0a4 —— 界面不再卡死

> 预发行版。这一版全是**修问题**，请优先拿它测。

## 修掉「下载时窗口未响应」

在公告里点「下载并安装」之后，主程序会卡住不动 —— 这是**真 bug**，原因在 Tauri 的一条规则：

`@text
Tauri 2 里，**不带 async 的命令跑在主线程上**。
主线程被占死 -> 窗口收不到消息泵 -> 用户看到的就是「未响应」。
`@

而下载要跑几十秒，于是整个下载过程窗口都是死的。

同一个坑**不止下载**：读整个压缩包、拷贝几个 GB 的战役、等用户选文件……
这些命令全都是同步的，全都会把界面卡住。所以这次**把命令层全部改成异步**：

`@rust
#[tauri::command(async)]
fn import_package(...) -> Result<...> { ... }
`@

`(async)` 让 Tauri 把函数体丢到线程池执行，**不用改写函数体**，一个词的事。
特别长的活（下载、检查更新）再加一层 `async fn` + `spawn_blocking`，
免得占着异步 worker 几十秒。

自查：`src-tauri/src/lib.rs` 里不应该再出现不带 `(async)` 的 `#[tauri::command]`。

## 公告里点下载，改成跳到更新面板

原来的流程是在公告里直接开始下载 —— 用户只看到一个不动的弹窗，既没有进度条也看不到日志，
很容易以为死机了。现在改成：

`@text
点「下载并安装」
   ↓
收起公告 -> 跳到设置页 -> 滚到更新面板
   ↓
在那里开始下载，进度条与内嵌终端全程可见
`@
