# v0.1.0a3 —— 更新提示看得见，项目走 PR

> 预发行版。这一版把「更新」从头到尾做成了**用户看得见的过程**，
> 顺便把仓库的协作流程改成 PR。

## 启动就知道有新版本

以前只有右上角一个小角标，容易被忽略。现在**每次启动检查一次，有新版直接弹公告**：

- 公告正文就是 GitHub Release 的 **Markdown 渲染结果** —— 标题、列表、表格、
  代码块、引用、链接都能正常显示
- 链接不会在启动器里跳转（那会把界面自己导航跑掉），一律交给系统浏览器
- 可以勾「**不再提示这个版本**」：勾了之后只留角标，等出更新的版本再弹

渲染这块有两道处理，缺一不可：

`@text
GitHub Release 正文 (Markdown)
        ↓  marked 解析
       HTML
        ↓  DOMPurify 净化
    安全的 HTML  →  插进页面
`@

正文说到底是**从网络来的数据**。就算仓库是自己的，也不该让一段正文有本事
往页面里塞 `<script>` 或 `onerror=`。

## 右上角的下载标记

有新版时顶栏右侧出现带**下载图标**的角标（向下箭头落进托盘），并轻微呼吸一下
把注意力引过来。点它直接跳到设置页的更新面板。

## 设置页：进度条 + 内嵌终端

- **进度条**：有总长度时按百分比推进；服务器没给 `@Content-Length`@ 时改成来回扫的
  不确定态，不假装知道进度
- **内嵌终端**：深色等宽，自动滚到底，逐行写清刚才做了什么。真实跑出来是这样：

`@text

[11:31:59] 网络：http://127.0.0.1:7897（Windows 系统代理）
[11:31:59] 查询 GitHub Releases…
[11:32:00] 代理被限流：HTTP 403 API rate limit exceeded for 58.152.46.170（剩余额度 0）
[11:32:00] 改用直连重试…
[11:32:00] 直连成功

下载完成后仍然会弹那个重启确认框。

## 项目改成 PR 流程

流向固定，**三个分支都开了保护，直推会被拒**：

`@text
feat/*  ─┐
fix/*   ─┼─→  dev  ─→  main  ─→  release  ─→  tag
chore/* ─┘
`@

PR 会被 CI 拦两件事：

| 检查 | 规则 |
| --- | --- |
| PR 标题 | 必须是 Conventional Commits（type + 主题行 ≤ 80 字符） |
| 目标分支 | 流向必须合法 —— 不许跳级，也不许把 main/release 倒回 dev |

另外补了 PR 模板、Issue 模板（缺陷 / 功能建议）与 `CONTRIBUTING.md`。

## 修的问题

- 对话框的 `.sheet` 系列样式原本写在某个组件的 `<style scoped>` 里，
  别的组件用同名类时**完全没有样式**（弹窗会退化成堆在页面末尾的普通方块）——
  已提到全局样式表
- 订阅更新事件时多了一层 `isDesktop` 判断，导致浏览器演示模式永远收不到日志
- CSP 的 `img-src` 放行 `https:`，公告里的截图才能显示
