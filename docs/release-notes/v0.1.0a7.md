# v0.1.0a7 —— 非同盘安装能用了

**这一版的主题：修一个让一部分用户完全用不了的问题 —— 启动器与游戏不在同一个盘时，启用/停用战役、铺模组全部失败。**

> **怎么升级**：覆盖 exe 即可。**用户数据（战役库、存档、配置）不受影响** ——
> 更新只换程序本体，`data/` 一个字节都不碰。

## 一、修掉的问题

| 症状（用户看到什么） | 原因 | 现在 |
| --- | --- | --- |
| 启动器装在**一个盘**、游戏在**另一个盘**时，启用 / 停用战役、铺模组一律失败；界面报错，游戏目录里什么都没变 | 那几处拿 `fs::rename` 在游戏目录与启动器的 `data/` 之间搬文件。`rename` **只在自己所在的卷内有效**，跨卷直接失败（Windows 上是 ERROR_NOT_SAME_DEVICE） | 先试 `rename`（同卷最快、原子），失败退回**复制 + 删源**；目录树与单文件都支持 |

绿色版默认装在软件同级目录 —— 玩家把启动器放 C 盘、游戏在 D 盘，这条**必然**踩。

### 两条底线写死在实现里

- 复制中途失败，先把写出去的那半删掉再报错（**不留半个目标**）；
- **删源只在复制完全成功之后**（宁可多留一份源，也不能出现「源没了、目标只写了一半」）。

### 换了哪 5 处

| 位置 | 干什么 |
| --- | --- |
| `library/install.rs` | 覆盖前把官方文件挪进 `data/backup/`；切回原版时还原 |
| `library/mods.rs` | 模组暂存区 → `data/mods/`；`%TEMP%` → 库 |

其余 12 处 `rename` **故意不动** —— 那些源和目标都在**同一个目录**里
（写临时文件再改名的原子替换）。换成新助手反而会让「崩在半路留下半个 JSON」重新出现。

## 二、怎么验证的

除常规门禁外，加了一条**默认忽略的真跨卷测试**（测试机不一定有第二个卷）：

```powershell
$env:MIYIN_CROSS_VOLUME='F:\'; cargo test -p miyin-core -- --ignored moves_across_volumes --nocapture
```

它**先断言裸 `rename` 确实失败**（否则这条测试根本没在验退路），再验目录树与单文件
都搬成功、源被删掉。开发机上 **C: → F:** 实跑通过。

## 三、已知问题 / 这一版没做的

- 跨卷复制不搬 **ACL 与备用数据流（ADS）**（`fs::copy` 的语义）。SC2 的战役与模组内容不依赖这些，
  但带 ADS 的文件没实测过。
- **进程中途被杀**会留下半个目标 —— 这是 `rename` 也给不了的保证：只有进程活着才能自己清干净。
  下一次启用/停用会自己收口（调用点都先删目标再搬）。
