# 0.1.0a7

这一版是**热修**：修一个让一部分用户完全用不了的问题。

## 非同盘安装能用了

**症状**：启动器装在**一个盘**、游戏在**另一个盘**的用户，启用 / 停用战役、铺模组
一律失败 —— 界面报错，游戏目录里什么都没变。

**根因**：那几处拿 `fs::rename` 在游戏目录与启动器的 `data/` 之间搬文件。
`rename` **只在自己所在的卷内有效**，跨卷直接失败（Windows 上是 ERROR_NOT_SAME_DEVICE）。
绿色版默认就装在软件同级目录 —— 玩家把启动器放 C 盘、游戏在 D 盘，这条必然踩。

**修法**：新增 `platform::move_path`：先试 `rename`（同卷最快、原子），
失败就退回**复制 + 删源**，目录树与单文件都支持。两条底线写死在实现里：

- 复制中途失败，先把写出去的那半删掉再报错（**不留半个目标**）；
- **删源只在复制完全成功之后**（宁可多留一份源，也不能出现「源没了、目标只写了一半」）。

换掉了 5 处真跨卷的调用点：

| 位置 | 干什么 |
| --- | --- |
| `library/install.rs` | 覆盖前把官方文件挪进 `data/backup/`；切回原版时还原 |
| `library/mods.rs` | 模组暂存区 → `data/mods/`；`%TEMP%` → 库 |

其余 12 处 `rename` 是**同一个目录内**的原子替换（写临时文件再改名），**故意不动** ——
换成新助手反而会让「崩在半路留下半个 JSON」重新出现。

## 验证

除常规门禁外，加了一条**默认忽略的真跨卷测试**，用 `MIYIN_CROSS_VOLUME` 打开：

```powershell
$env:MIYIN_CROSS_VOLUME='F:\'; cargo test -p miyin-core -- --ignored moves_across_volumes --nocapture
```

它先断言**裸 `rename` 确实失败**（否则这条测试根本没在验退路），再验目录树与单文件
都搬成功、源被删掉。开发机上 **C: → F:** 实跑通过。
