# 0.1.0a7

**本版本为热修复版本。修复启动器与游戏安装于不同磁盘分区时，无法启用战役与模组的问题。**

## 升级方式

覆盖可执行文件即可。本版本不修改用户数据（战役库、存档、配置），`data/` 目录内容保持不变。

## 一、问题与修复

### 现象

启动器与《星际争霸 II》安装于**不同磁盘分区**时，启用或停用战役、安装模组均失败；
界面返回错误信息，游戏目录内容无变化。二者位于同一分区时不受影响。

### 原因

相关实现使用 `fs::rename` 在游戏安装目录与启动器 `data/` 目录之间移动文件。
`fs::rename` 仅在同一卷内有效，跨卷调用必然失败（Windows 错误码 `ERROR_NOT_SAME_DEVICE`）。
绿色版启动器默认安装于程序同级目录，因此启动器位于 C 盘、游戏位于 D 盘时，该问题必然出现。

### 修复内容

新增 `platform::move_path`，其行为如下：

1. 优先调用 `fs::rename`。同一卷内为原子操作，开销最低。
2. 调用失败时，退化为「复制后删除源路径」。支持单个文件与目录树。

实现包含两项约束：

- 复制过程中失败时，先删除已写入的部分，再返回错误，不保留不完整的目标路径。
- 仅在复制完全成功后删除源路径。

### 受影响调用点

| 模块 | 操作 |
| --- | --- |
| `library/install.rs` | 覆盖前将被覆盖的官方文件移入 `data/backup/`；切回原版时执行还原 |
| `library/mods.rs` | 模组暂存目录至 `data/mods/`；`%TEMP%` 至模组库 |

以上共 5 处，已全部改用 `platform::move_path`。

其余 12 处 `fs::rename` 调用**未作改动**。这些调用的源路径与目标路径位于同一目录，
属于「写入临时文件后改名」的原子替换操作。改用 `move_path` 将失去原子性，
进程异常终止时可能残留不完整的 JSON 文件。

## 二、验证

除常规质量门禁外，新增一项默认忽略的跨卷测试，通过环境变量启用。

```powershell
$env:MIYIN_CROSS_VOLUME='F:\'
cargo test -p miyin-core -- --ignored moves_across_volumes --nocapture
```

该测试首先断言 `fs::rename` 在跨卷场景下确实失败（否则该测试未覆盖退化路径），
随后验证目录树与单个文件均移动成功，且源路径已被删除。

开发机验证结果（源位于 C 盘，目标位于 F 盘）：

## 三、已知限制

1. **复制过程不保留 ACL 与备用数据流（ADS）。** `fs::copy` 的语义仅包含常规属性与时间戳。
   星际争霸 II 的战役与模组内容不依赖上述属性；包含 ADS 的文件未经实测。
2. **进程被强制终止时，可能残留不完整的目标路径。** 该情况无法由 `move_path` 消除，
   仅在进程正常返回错误时可完成清理。下次执行启用或停用操作时会自动收敛，
   因为所有调用点均先删除目标路径，再执行移动。

## 四、影响范围

- 版本号：`0.1.0-alpha.6` 至 `0.1.0-alpha.7`（`Cargo.toml`、`ui/package.json`、`src-tauri/tauri.conf.json` 三处一致）。
- 代码改动位于 `miyin-core`：`platform.rs` 新增助手函数与 5 项测试；5 处调用点各修改一行。
- 未包含前端改动。未修改包格式。未新增依赖。
