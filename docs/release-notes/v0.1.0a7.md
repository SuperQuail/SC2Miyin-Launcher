# 0.1.0a7

## 非同盘安装能用了（这一版的重点）

**症状**：启动器装在**一个盘**、游戏在**另一个盘**的用户，启用 / 停用战役、铺模组一律失败。

**根因**：那几处拿 `fs::rename` 在游戏目录与启动器的 `data/` 之间搬文件。
`rename` **只在自己所在的卷内有效**，跨卷直接失败（Windows 上是 ERROR_NOT_SAME_DEVICE）。
启动器默认就装在软件同级目录 —— 玩家把绿色版放 C 盘、游戏在 D 盘，这条必然踩。

**修法**：新增 `platform::move_path`：先试 `rename`（同卷最快、原子），
失败就退回**复制 + 删源**，目录树与单文件都支持。两条底线写死在实现里：

- 复制中途失败，先把写出去的那半删掉再报错（不留半个目标）；
- **删源只在复制完全成功之后**（宁可多留一份源，不能出现「源没了、目标只写了一半」）。

换掉了 5 处真跨卷的调用点（覆盖前把官方文件挪进 `data/backup/`、切回原版时还原、
模组暂存区与导入）。其余 12 处 `rename` 是**同目录内**的原子替换，故意不动 ——
换成新助手反而会让「崩在半路留下半个 JSON」重新出现。

**验证**：除常规测试外，加了一条默认忽略的真跨卷测试，在 **C: → F:** 上实跑通过；
它先断言裸 `rename` 确实失败，否则不算验到退路。

这一版很小，只补一处：**打包没完的时候别让人走掉**。

## 打包没完就想走，会拦一下

一次导出要写几十秒到几分钟。中途离开（点返回、关窗口、刷新）留下的是**写了一半的包** ——
拿它去导入只会看到「包内没有 metadata.json」，而用户完全不知道是导出没写完。

所以离开这件事被改成**一次明确的取消**：

- **不取消** —— 关掉问句，留在页面上，导出照旧继续；
- **取消导出并离开** —— 后端在下一个文件写完时停手，**把写了一半的包删掉**，然后才放人走。
  取消不是"把界面关掉、后台接着写"：包要么是完整的，要么不存在。

三条路都拦住了：

| 怎么走 | 怎么拦 |
| --- | --- |
| 点「← 返回启动器」 | 自己的对话框：「还在打包 123/2331。离开就得先取消这次导出 —— **写了一半的包会被删掉**」，给「不取消」与「取消导出并离开」 |
| 关窗口（✕ / 任务栏） | 桌面壳的 `onCloseRequested` 拦下，弹同一个框 |
| 刷新 / 关标签页 | 浏览器级的 `beforeunload` |

## 流程约定

- **除非用户明确说明，不得发布 PR**：改动先待在分支上，等一句话再开。
- **代理不许代替维护者 merge**：开 PR、跑门禁、贴验证是代理的活，merge 只能由维护者自己做。
