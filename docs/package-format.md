# 弥音战役包 / 补丁包格式 v2

> 本文档是**包作者**与**启动器实现**之间的契约，也是格式的唯一权威。
> 实现见 `crates/miyin-core/src/campaign/` 与 `library/`。

## 0. 设计目标

1. **兼容既有生态**：CCM 与「星际枢纽」的包不改一个字节也能导入；我们导出的包 CCM 也能直接读。
2. **扩展不冲突**：我们的东西放在 `miyin` 命名空间与 `Miyin/` 目录里，老工具忽略即可。
3. **格式版本可协商**：包声明的版本高于启动器支持时**明确拒绝**，而不是猜着解析。
4. **包不能决定落点**：包内路径只是"建议落点"，最终由启动器校验后决定。
5. **战役与补丁都可恢复**：任何叠加都不破坏原始数据，随时能退回。

## 1. 战役包

### 1.1 容器与形态

**任意打包形式都收，不用你转格式**：

| 格式 | 怎么读 |
| --- | --- |
| **zip** | 原生读（快路径，也是绝大多数包的形态） |
| **7z / rar / tar / cpio / …** | 交给系统自带的解压器解到临时目录，再按目录遍历 |

Windows 10 1803+ 自带的 `tar.exe` 其实就是 **bsdtar（libarchive）**，
一个工具覆盖 zip / tar / 7z / **rar5** / cpio —— 所以"兼容任意打包形式"不需要任何额外安装。
找不到 `tar` 时再依次试 7-Zip、UnRAR。

实测：`枪兵之翼1.03幼儿园就这版 CCM.7z`（49 MB）与
`平衡x2虫心（有单位升级）.rar`（186 MB，RAR5）都能直接导入，中文路径也解对了。

按下面的优先级识别四种形态：

| 形态 | 判据 | 兼容对象 |
| --- | --- | --- |
| 标准包 | **包根**有 `metadata.json` | 星际枢纽标准 |
| CCM 包 | 包内任意层级有 `metadata.txt` | CCM 生态 |
| 镜像包 | 包内出现 `Maps/` 或 `Mods/` 顶层目录 | 玩家手工打包（见 §1.4） |
| 最小地图包 | 只有 `.SC2Map`（文件或目录），没有任何元数据 | 玩家手工打包（见 §1.5） |

`.rar`、`.7z` **不支持**，会明确提示（转换方法：解压后重新打成 zip）。

### 1.2 元数据

两种写法都支持，字段一致：

- `metadata.txt`：`键=值` 逐行，**大小写不敏感**，值取第一个 `=` 之后的内容
- `metadata.json`：JSON，我们自己的扩展放在 `miyin` 对象里

| 键（txt） | 字段（json） | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | `name` | 否 | 显示名。缺失时用压缩包文件名 |
| `desc` | `description` | 否 | 描述 |
| `author` | `author` | **建议** | 作者。缺失时记为「未知作者」 |
| `campaign` | `campaign` | **建议** | 归属资料片，见 §1.6 |
| `version` | `version` | 否 | 自由字符串，但**至少要能比**：见下 |
| `id` | `id` | 否 | **注册 ID**，见 §1.3 |
| `cover` | `cover` | 否 | 封面图相对路径 |
| `tags` | `miyin.tags` | 否 | 标签，逗号 / 顿号 / 空格分隔 |
| — | `miyin.format` | 否 | 扩展格式版本，当前 `1` |
| — | `miyin.kind` | 否 | `campaign`（默认）/ `patch` |

**版本号的规则**：格式自由（`1.2`、`v8.0.1`、`1.0.2a2` 都行），但必须**含至少一个数字**，
且只用字母、数字、`.`、`-`、`_`、`+`。

> 为什么：导入时判断「这是新版本还是旧版本」靠的是抽数字段比较
> （`compare_versions`）。一个不含数字的版本号没法比 —— 那种情况下启动器只能
> 说"认不出来"，界面也就没法提示"你导入的是旧版"。**不写版本号是可以的**，
> 写了就得能比。

### 1.3 注册 ID

**用途**：补丁靠它引用战役；更新时靠它认出"这是同一个战役的新版本"。

- 建议写法：`<作者短名>.<战役短名>`，例如 `HTXL.golden-lotv`、`小白.幼儿园补丁`
- 允许中文、字母、数字、`.`、`-`、`_`；大小写不敏感
- **缺失时由启动器生成**：`auto-<8 位随机>`，并写回战役记录
- **可以编辑**：用户在启动器里改 ID 会同时更新补丁的引用

### 1.4 包内布局：镜像

玩家手工打的包经常直接就是游戏目录的样子：

```text
Maps/Campaign/void/metadata.txt      <- 元数据也在这里
Maps/Campaign/void/epiloguestory01.SC2Map/...
Maps/Campaign/voidprologue/...
Mods/SomeMod.SC2Mod/...
```

启动器会**识别这种镜像结构**并把 `Maps/`、`Mods/` 作为落点依据（仍然要过白名单校验），
而不是把整棵 `Maps/` 树塞进战役目录。

**只认规范拼写 `Maps/` / `Mods/`**：包作者拿小写 `maps/` 当普通内容目录用的情况很常见，
一律按镜像处理会把它们误送到游戏根下。

### 包内相对目录怎么解释

包里出现子目录时，它的含义**取决于内容根站在哪里**（两个真实样本教给我们的）：

| 情形 | 样本 | 规则 |
| --- | --- | --- |
| 内容根**已经落在**官方战役目录里（`X/swarm/metadata.txt`） | 酒馆合作虫心 | 包内相对路径是**该战役目录之内**的结构，原样保留：`evolution/y.SC2Map` → `Maps/Campaign/swarm/evolution/y.SC2Map` |
| 内容根是包根，顶层就是**官方目录名** | 净化者纪元幼儿园 | 那是绝对路径：`voidprologue/y.SC2Map` → `Maps/Campaign/voidprologue/y.SC2Map` |
| 内容根是包根，顶层是**任意分类目录** | `maps/01.SC2Map` | 没有游戏语义，只取文件名：→ `Maps/Campaign/void/01.SC2Map` |

判错的后果很实在：进化地图被摆到虫心主目录、序章地图被摆进虚空之遗主目录 ——
游戏都找不到。见 `payload_target` 与 `known_campaign_prefix`。

### 1.5 最小地图包

只有地图、没有任何元数据的包，同样能导入：

- **战役名** = 压缩包文件名（去扩展名）
- **作者** = `未知作者`
- **归属战役**按地图名推断（见 §1.6），推不出来就让用户选
- 地图保持原形态（单文件 MPQ 或解开目录）

### 1.6 地图载体与归属推断

地图有两种合法载体，**两者都支持**，落盘时保持原形态：

| 载体 | 例子 |
| --- | --- |
| 单文件 MPQ | `paiur01.SC2Map`（一个 1 MB 的文件） |
| 解开目录 | `paiur01.SC2Map/`（里面是 `Base.SC2Data/` 等） |

`campaign` 字段缺失时，用地图名首字母推断官方战役（暴雪官方地图的命名约定）：

| 首字母 | 归属 | 例子 |
| --- | --- | --- |
| `t` | 自由之翼 | `traynor01`、`ttychus01` |
| `z` | 虫群之心 | `zchar01`、`zlab02` |
| `p` | 虚空之遗 | `paiur01`、`pkorhal01` |
| `n` | 诺娃隐秘行动 | `nprologue01` |

`campaign` 的取值容错匹配：`WOL`/`wings`/`liberty`、`HOTS`/`swarm`、
`HOTSEVO`/`evolution`、`LOTV`/`void`/`legacy`、`LOTVPROLOGUE`/`prologue`、`NCO`/`nova`。

## 1.7 归属判定：普通压缩包怎么自动认出属于哪部战役

大量玩家自制包**根本不是 CCM 包**：没有元数据、没有目录结构，就是一个塞满地图的 zip。
启动器按下面四层依次判定，**每一层都记下依据**，界面会如实告诉用户"凭什么这么判"：

| 顺序 | 证据 | 精确? | 例子 |
| --- | --- | --- | --- |
| 1 | 元数据里的 `campaign` 字段 | ✅ | `campaign=LotV` |
| 2 | 包内镜像路径 | ✅ | `Maps/Campaign/void/paiur01.SC2Map` |
| 3 | **地图内部的依赖声明** | ✅ | `bnet:Void Story (Campaign)/0.0/999` |
| 4 | 地图文件名前缀 | ⚠️ 启发式 | `paiur01.SC2Map` → `p` |

四层都认不出来就**停下来让用户选**，绝不瞎猜。

### 第 3 层是怎么做到的

SC2 的 `.SC2Map` 是 **MPQ v4** 归档（用 HET/BET 表），完整解析成本很高。
但暴雪自己的依赖系统把战役依赖写在 `DocumentHeader` 里：

```text
bnet:Void Story (Campaign)/0.0/999,file:Mods\LotV-Fight with ally!.SC2Mod
```

所以：

- **展开形态**（`xxx.SC2Map/DocumentHeader`）：那个小文件就在包里，直接读
- **单文件 MPQ**：`DocumentHeader` 是一个 zlib 流，**扫出来解压即可**，不用碰 MPQ 容器

实测覆盖率（每个包取前 8 张地图）：

| 样本 | 扫到 | 命中 | 判定 |
| --- | --- | --- | --- |
| 净化者纪元幼儿园 | 8 | 8 | 虚空之遗 |
| 利维坦AI虫心重置版 | 8 | 8 | 虫群之心 |
| 精英虫心轨道支援 | 8 | 8 | 虫群之心 |
| 酒馆合作虫心 | 8 | 8 | 虫群之心 |
| 黄金之遗 | 8 | 8 | 虚空之遗 |
| AI盟友虚空之遗 | 8 | 3 | 虚空之遗（作者改过地图，只有 3 张保留声明） |

这条路的威力在于：**地图可以取任意文件名**。把 `酒馆合作虫心` 的 6 张地图改名成
`stage01~06.SC2Map`（不含任何 `t/z/p/n` 前缀）单独打包，照样判出「虫群之心」。

### 拿不到时会怎样

判定链继续往下走，绝不会把"扫不到"当成"没有依赖"。

依赖名的映射（忽略大小写、空格、连字符）：

| 声明里的名字 | 归属 |
| --- | --- |
| `Liberty` / `Wings of Liberty` | 自由之翼 |
| `Swarm` / `Swarm Story` | 虫群之心 |
| `Swarm Evolution` | 虫群之心（进化，目标 `swarm/evolution`） |
| `Void` / `Void Story` | 虚空之遗 |
| `Void Prologue` | 虚空之遗（序章） |
| `Nova` / `Nova Story` | 诺娃隐秘行动 |

多条声明取**出现次数最多**的，且**并列第一就作废**（分不清宁可交给用户）。

### 自动做成战役包

判定成功后，无元数据的普通包会被补上：

- **战役名** = 压缩包文件名（去扩展名）
- **作者** = `未知作者`
- **归属** = 判定结果
- **注册 ID** = 导入时生成，之后可用「编辑」改成正式 ID

## 1.8 导入流程：数据优先，识别兜底，手动保底

三层，**从上到下**，任何一层不成立就往下走：

| 顺序 | 依据 | 性质 |
| --- | --- | --- |
| 1 | 包内的 CCM `metadata.txt` / 弥音 `metadata.json` | **以数据为准** —— 名字、作者、版本、ID、归属全按它来 |
| 2 | 证据链自动识别（§1.7 的四层） | **尽力而为** —— 界面会如实标注"自动识别" |
| 3 | 用户手动指定 | **永远可用，且优先级最高** |

### 手动指定为什么永远要有

自动识别再准也只是猜。作者可能用了自定义命名、改了地图依赖、或者干脆打了个从没人见过的包。
所以界面上**始终**提供"导入到哪部战役"的选择，并默认填好自动识别的结果 ——
用户直接确认就行，不对就改。`import_package` 传了 `slot` 就按传的来，
不再走自动判定。

### 界面要如实措辞

`prepare_import` 会返回 `source` 字段：

| `source` | 含义 | 界面措辞 |
| --- | --- | --- |
| `metadata` | 包内元数据说了算 | 「包内声明的资料片：虚空之遗」 |
| `inferred` | 自动识别（尽力而为） | 「自动识别：虚空之遗（依据：地图内的依赖声明）」 |
| `manual` | 认不出来 | 「无法识别，请选择要导入到哪部战役」 |

**不要把 `inferred` 说成确定的** —— 见 `CampaignEvidence::is_exact()`。


### 战役类型：原版改版 vs 自制战役

`campaign` 字段现在接受第四类取值：

| 写法 | 归入 | 落盘位置 |
| --- | --- | --- |
| `WOL` / `wings` / `liberty` | 自由之翼 | `Maps/Campaign/…` |
| `HOTS` / `swarm` | 虫群之心 | `Maps/Campaign/swarm/…` |
| `HOTSEVO` / `evolution` | 虫群之心 · 进化 | `Maps/Campaign/swarm/evolution/…` |
| `LOTV` / `void` | 虚空之遗 | `Maps/Campaign/void/…` |
| `LOTVPROLOGUE` / `prologue` | 虚空之遗 · 序章 | `Maps/Campaign/voidprologue/…` |
| `NCO` / `nova` | 诺娃隐秘行动 | `Maps/Campaign/nova/…` |
| **`custom` / `自制`** | **自制战役** | **`Maps/CustomCampaigns/<包名>/…`** |

前六类是**对官方战役的改版**，界面上归在「原版战役」组；
`custom` 是**独立做的整部战役**，归在「自制战役」组。两者不是一类，别混。

写了 `custom` 之后建议把版本也写上，便于版本管理：

```text
campaign=custom
version=1.2          # 冲突时可选「覆盖更新」或「重命名后导入」
```

没写 `campaign` 时启动器会按 §1.7 的证据链去猜；**认出来也不影响你手动改**，
但高置信度被强改时会弹窗提醒一句（装错地方多半玩不了）。

### modid：模组的身份

`modid` 决定「这是同一个模组的新版本，还是另一个模组」。不写就退回用名字当 id。

```text
modid=quail.armory
version=2.4
```

导入时按下面四条处理：

| 情况 | 处理 |
| --- | --- |
| 库里没有这个 id | 新模组 |
| 有，且**内容一模一样**（SHA-256 相同） | **不留第二份**，直接用库里那份 |
| 有，版本号不同 | 作为**新版本**归到同一个模组下面，可自由切换 |
| 有，版本号相同但内容不同 | **自动改个版本号**再存（`1.2` -> `1.2.2`） |

**版本号优先用包内声明的**。没声明才从库里已有的推 —— 推出来的多半跟上一版同号，
于是自然走到「撞号改名」那条路。不知道版本就老实说不知道，别硬安一个。

导入时如果库里已经有同 id 的，启动器会**问一句**：

- **作为新版本** —— 归到一起，之后可以切换用哪一版（同一时刻只能启用一个，
  它们在游戏 `Mods/` 里抢同一个文件夹）
- **作为独立改版** —— 单独显示一个。适用于「拿别人的模组改的」，它跟原版是两码事

### 对比与选择性导出

装了 SC2Diff 之后，同一个模组的两个版本可以**对比**：列出文件级差异，
并对能比较的文档跑**语义 diff**（改了什么字段/物件）。
没装就只列文件级差异，界面会如实说明。

导出时**勾选要带哪几个版本** —— 一个模组攒了十几个版本之后全打包又大又没人要，
而「把 1.0 和 1.3 一起发过去对比」是很实际的需求。

### 依赖模组：`mods=`

地图可能需要若干个模组才能正常打开。作者在元数据里声明它们，启动器就会：

- **导入时全挂上**（默认），用户点启动就能跑
- 在模组管理页给它们打「依赖」标
- 声明了却没打进包，导入时给一条警告 `MOD_MISSING`

```text
campaign=wol
version=2.4
mods=Alenger, kit_liberty_story.SC2Mod
```

**模组按文件夹分，不按单个文件分。** 这是从真实样本（疯批帝国军械库 2.4）学到的：

```text
Mods/
├── 3疯批帝国之翼.SC2Mod        单文件         -> 一个模组
├── Alenger/                    普通文件夹     -> 一个模组
│   ├── 1钢铁.SC2Mod                            （里面 18 个 .SC2Mod）
│   └── …
└── kit_liberty_story.SC2Mod/   解开目录树     -> 一个模组
```

判定办法：取落点里 `Mods/` 之后**第一段**。
所以 `Alenger` 写一次就够了，不用把 18 个文件全列出来。

写名字时前缀和后缀都可以省，下面四种写法等价：

```text
Mods/Alenger
Mods/Alenger/
Alenger
Alenger.SC2Mod
```

中文名也照常（`mods=3疯批帝国之翼`）。

### 自制战役的两个新键：`main_map` 与 `doc`

只有 `campaign=custom` 的包用得上这两个。

```text
campaign=custom
version=1.2
main_map=1. Rebel Yell/Terran01.SC2Map
doc=说明.pdf
```

| 键 | 别名 | 作用 |
| --- | --- | --- |
| `main_map` | `mainmap` / `main` | **主地图**：打开就能一路玩到底的那张入口地图 |
| `doc` | `document` / `manual` / `说明` | **说明文档**（PDF），启动器里能直接读 |

两条约定：

1. **路径用相对路径、斜杠统一用 `/`**。只写文件名也能认，但不同章节里可能有
   重名地图（`Terrain01` 这种），写全相对路径最稳。
2. **找不到只警告，不阻断**。主地图写错了会提示「找不到这张地图，请自己挑一张」，
   导入照常完成 —— 作者改了章节名而忘了改 `main_map` 是很常见的事。

`main_map` 没写时：包里只有一张地图就自动用它；多张就不猜，让用户在界面上挑。
用户挑完会写回启动器自己的索引，**覆盖包里的声明**（不动原包）。

`doc` 没写时按文件名特征找：`说明` / `readme` / `manual` / `doc` /
`guide` / `攻略`，都没有就取根目录下第一份 PDF。

说明文档和封面一样，**连包一起解开后就留在版本目录里**，
启动器读它不需要再碰原压缩包。

## 2. 补丁包

### 2.1 什么是补丁

补丁是**覆盖层**：它本身不是战役，而是往已有战役上叠的一层文件。
真实补丁的说明文件原话就是「将本目录中的 `X.SC2Mod` 文件夹**覆盖**到星际争霸 II 的 `Mods` 目录中」。

### 2.2 元数据

补丁**不强制**带元数据（现实中的补丁常常只有一个 `说明.txt`）。
需要声明依赖时，三种写法任选：

```json
{
  "miyin": {
    "kind": "patch",
    "id": "xiaoBai.kindergarten-v3",
    "name": "肉鸽之心 幼儿园补丁 V3",
    "author": "小白的心之所念",
    "patch": {
      "requires": ["KerriganRogue"],
      "priority": 100
    }
  }
}
```

```ini
# patch.txt（CCM 风格，补丁专用；与 metadata.txt 可同时存在）
name=肉鸽之心 幼儿园补丁 V3
author=小白的心之所念
id=xiaoBai.kindergarten-v3
requires=KerriganRogue, 肉鸽之心
priority=100
```

### 2.3 依赖规则

| `requires` | 类型 | 用法 |
| --- | --- | --- |
| 非空 | **完全补丁** | 启动器**自动检测**已导入的战役里有没有满足依赖的；有就自动挂上，没有则提示并允许手动指定 |
| 空 / 没有元数据 | **通用补丁** | 不自动匹配，**只能手动**指定要打给哪个战役 |

匹配规则：`requires` 里的每一项与战役的**注册 ID** 或**战役名**比对，大小写不敏感。

### 2.4 覆盖与优先级

- 一个战役可以挂**任意多个**补丁
- 每个补丁有 `priority`（整数，默认 `100`）；**数值大的后覆盖**，即优先级高
- 优先级相同时，按挂载顺序（先挂的先被覆盖）
- 同一路径在多层里出现时，只有最高优先级那一层的内容会落到游戏目录

### 2.5 分层合成（为什么省空间）

启动器**不复制**战役本体去给每个补丁做副本，而是把每次"打补丁"当成一次**合成**：

```text
第 0 层  data/campaigns/<战役>/<版本>/     战役本体
第 1 层  data/patches/<补丁id>/             优先级 100
第 2 层  data/patches/<补丁id>/             优先级 200
------------------------------------------------------
合成结果 = 每个相对路径取"最高优先级那一层"的文件
```

- **省空间**：补丁内容全程只存一份
- **可恢复**：合成不改动任何原始层；铺进游戏目录的文件全部记账，撤下即还原
- **开关快**：勾掉一个补丁 = 重新合成一次（只重算受影响路径）

### 2.6 补丁的落点

补丁内的路径同样支持两种写法：

| 包内路径 | 落点 |
| --- | --- |
| `Mods/Foo.SC2Mod/...` | `<游戏>/Mods/Foo.SC2Mod/...` |
| `Foo.SC2Mod/...`（裸的） | `<游戏>/Mods/Foo.SC2Mod/...` |
| `Maps/Campaign/void/...` | `<游戏>/Maps/Campaign/void/...` |

裸 `.SC2Mod`、`.SC2Map` 会自动补上 `Mods/`、`Maps/` 前缀 —— 这是现实补丁最常见的形态。

## 3. 导出

### 3.1 CCM 可直接读

导出的包**默认按 CCM 形态**组织：

```text
<战役名>.zip
├── metadata.txt            # CCM 读这个
├── paiur01.SC2Map          # 平铺的地图
├── paiur02.SC2Map
├── HTXL.SC2Mod             # 平铺的模组
└── Miyin/                  # 我们的额外数据，CCM 不读也不冲突
    ├── metadata.json
    ├── cover.png
    └── patches/…
```

- CCM 只认根目录的 `metadata.txt` 与平铺的 `.SC2Map`/`.SC2Mod`，**`Miyin/` 目录对它完全透明**
- 我们的 `metadata.json` 放在 `Miyin/` 里，因此**不会**和 CCM 的 `metadata.txt` 抢位置

### 3.2 带补丁导出

两种模式：

| 模式 | 行为 |
| --- | --- |
| **附加模式**（默认） | 补丁原样放进 `Miyin/patches/<id>/`，并写 `Miyin/bindings.json` 记录优先级与启用状态；导入方可以继续单独开关 |
| **合成模式** | 把启用中的补丁**合并进顶层文件**，导出物是"打完补丁的样子"；同时仍在 `Miyin/` 里保留原始补丁 |

## 4. 启动器的安全约定

| 风险 | 处理 |
| --- | --- |
| 条目名含 `..`、绝对路径、盘符 | **拒绝整个包**（zip-slip） |
| 元数据里的名字不可用（`..`、保留名、空） | 安全化后使用，退回压缩包名 |
| 解压后体积 / 条目数超限 | 拒绝（8 GiB / 100000 条） |
| 元数据编码 | UTF-8 优先，失败退回 GBK |
| 落点路径 | 由启动器拼接，并做白名单与包含性校验 |
| 包内镜像路径（`Maps/`、`Mods/`） | 只作为**建议**，仍要过白名单 |

## 5. 版本演进

- 新增**可选**字段不提升版本号（老启动器忽略即可）。
- 改变既有字段语义、或新增启动器**必须理解**才能正确安装的字段时，提升 `miyin.format`。

`miyin.format` 目前三档，**启动器支持到 3**（`MIYIN_FORMAT_VERSION`）：

| 格式 | 含哪些字段 | 说明 |
| --- | --- | --- |
| `1` | name / author / version / campaign / id / cover / tags | 基础字段 |
| `2` | 加上 kind / priority / requires | 补丁字段 —— **必须理解**才不会装错 |
| `3` | 加上 overrides | 覆盖规则（v3 草案已实现） |

**导出时按"实际用到了哪一档"声明**：没写补丁字段就别报 2 —— 多报会让老启动器
白白拒绝你的包，少报会让它按老语义解析新字段。两条都糟。

包声明的 `miyin.format` 高于启动器支持时会**明确拒绝**，不会猜着解析。
