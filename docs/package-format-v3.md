# 弥音战役包 / 补丁包格式 v3（草案）

> **这是草案，不是契约。** 定稿前以 [`package-format.md`](./package-format.md)（v2）为准。
> 讨论见 issue #17；v3 落地时本文并入 `package-format.md` 并把版本号提到 3。

## 0. 为什么要有 v3

v2 的落点是**推出来的**：启动器看包长什么样，自己算该装到哪（`package.rs` 的 `payload_target`
加 `library/compose.rs` 的 `Placement`）。四条规则覆盖了绝大多数现实包：

| 包里长什么样 | 落到哪 |
| --- | --- |
| 镜像 `Maps/…` / `Mods/…` | 原样 |
| 平铺的地图 | `Maps/Campaign[/子目录]/` |
| 平铺的模组 | `Mods/<名字>` |
| 自制战役的地图 | `Maps/CustomCampaigns/<版本目录>/` |

但有三件事表达不了：

1. **不是地图也不是模组的文件，一律看不见。** 载荷只认路径里第一个以 `.SC2Map`/`.SC2Mod`
   结尾的组件（`package.rs` 的 `payload_root`），其余文件**静默丢掉**。
   最硬的一个例子是 `Interfaces/`：白名单放行它，但从 `has_mirror_root` 到 `game_relative`
   都不认这个名字，全仓库零处提到 `.SC2Interface` —— 界面 Mod 现在装不进去，
   而且是**没有提示地**装不进去。
2. **固定落点不够用。** 散装地图想进 `Maps/Starcraft Mass Recall/`，只有上面那三条路。
   复刻战役落对位置靠的是"作者把包摆成了游戏目录镜像"，不是靠声明。
3. **一个包分头落做不到。** 一半进 `Mods/`、一半进 `Maps/X/`，只能手工摆镜像，
   而且只有**顶层**出现 `Maps`/`Mods` 才算镜像（`has_mirror_root` 只看第一段）。

CurseForge 的整合包早就用一条规则解决了同一类问题：`manifest.json` 里声明一个
**覆盖文件夹**（`overrides`），它的内容在装完模组之后**原样铺到实例根目录上**，
路径就是实例内的相对路径。v3 抄这个思路。

## 1. 覆盖文件夹（overrides）

### 1.1 声明

JSON（`metadata.json` 的 `miyin` 对象里）：

```json
{
  "name": "复刻战役",
  "author": "某人",
  "campaign": "custom",
  "miyin": {
    "format": 2,
    "overrides": [
      { "from": "overrides" },
      { "from": "extra", "to": "Maps/Starcraft Mass Recall" }
    ]
  }
}
```

CCM 的 `metadata.txt` 也认，键名 `overrides`（可重复出现，一行一条）：

```ini
title=复刻战役
author=某人
campaign=custom
overrides=overrides
overrides=extra
format=2
```

> txt 形式**只能表达原样覆盖**：`key=value` 一行写不下 `to`。
> 另外 `format` 是 `miyin.format` 在 txt 里的写法 —— v2 的文档里没有这个键，v3 补上（见 §3）。

### 1.2 两种规则，够用了

| 形式 | 名字 | 含义 |
| --- | --- | --- |
| `{ "from": "overrides" }` | **原样覆盖** | `overrides/` 里的相对路径**就是**游戏目录内的相对路径：`overrides/Maps/X` → `<游戏>/Maps/X` |
| `{ "from": "extra", "to": "Maps/Starcraft Mass Recall" }` | **前缀映射** | `extra/1. Rebel Yell/Terran01.SC2Map` → `<游戏>/Maps/Starcraft Mass Recall/1. Rebel Yell/Terran01.SC2Map` |

`to` 省略 = 原样覆盖。`to` 末尾有没有 `/` 都一样。

**不做**通配、排除、条件规则。规则越少，装错的机会越少；真需要筛文件，
作者在打包时筛一遍就行。

### 1.3 落点由谁说了算

**显式声明优先于约定推断。** 一条包内路径如果同时被"覆盖规则"和 v2 的推断规则命中，
以覆盖规则为准，**不报错**（这是作者明确写的，不是冲突）。

但两条**覆盖规则**同时命中同一条路径 → **拒绝整个包**，并说清是哪两条。
"同一路径由谁落"必须唯一，猜不得。

同一个 `to` 前缀被多条规则叠？按声明顺序铺，后面的赢（与补丁分层同一套语义，
见 §2.4）。

### 1.4 覆盖文件夹里放什么

**什么都行**，这正是它存在的理由：

- `.SC2Map` / `.SC2Mod` —— 仍然是**载荷**：照样计入条目数、解压体积、模组识别，
  照样在版本管理里看得到。区别只有一个：**落点不再靠猜**，按规则来。
- 其它任何文件（`.SC2Interface`、`.dds`、`.xml`、`LocalizedData/*`）——
  v2 里会被静默丢掉，v3 里由规则接管。

两类都一样地由规则决定落点 —— **落点不做限制**，见 §2。

### 1.5 与既有形态共存

v2 的行为**一个字节都不改**：

- 一条覆盖规则都不写的包，照旧走全部旧规则（平铺 / CCM / 镜像 / 最小地图包）
- 写了才走新路，而且只对新路覆盖的那些路径生效
- 两者可以同时存在：没被规则命中的载荷仍按 v2 推断落点

## 2. 落点：不限制，但必须能完全还原

**决策：落点不再限制在 `Maps` / `Mods` / `Interfaces` 之内 —— 保证开发自由度。**
`to` 可以指向游戏目录里的任何位置。

代价要写在明面上：**包因此有能力覆盖游戏本体、覆盖启动器自己、覆盖用户文档。**
安全网换成两条（细节见 [`developer-workflow.md`](./developer-workflow.md) §2）：

1. **强制快照**：任何会被**覆盖**或**删除**的既有文件，动它之前先原样备份
   （硬链接优先，跨卷退回复制），之后能一键完全还原。不是可选项。
2. **知情同意**：导入时把变更清单（新增 / 覆盖 / 删除 / 体积）摆出来，
   落在游戏目录之外的路径单独标红，勾一下才继续。这是知情，不是禁止。

仍然拒绝的几条，**理由都不是"安全"，而是"没有意义或必然出错"**：

| 情形 | 处理 | 理由 |
| --- | --- | --- |
| 条目名含 `..`、绝对路径、盘符 | 拒绝整个包 | 它在 `from` 内部没有意义，只会是打包打错了 |
| `from` 指向包外 | 拒绝 | 同上：包内相对路径是唯一说得通的解释 |
| `from` 是包根本身 | 拒绝 | 那等于"整个包覆盖游戏目录"，元数据、`Miyin/` 全在里面 |
| 覆盖规则指向不存在的目录 | 拒绝整个包（不是"跳过"） | 作者改了目录名忘了改声明，必须让他知道 |
| 符号链接 / 硬链接 | 暂不做 | **不是安全**：备份和还原对它没有意义（记链接还是记目标？） |

体积上限（`MAX_UNPACKED_BYTES` 8 GiB / 100000 条）**仍然生效**，覆盖文件一样计入 ——
这条防的是"把磁盘写满"，不是防作者。

> CurseForge 那边 `overrides` 指到包根是可以的。我们仍然拒绝包根，
> 因为我们的包根还放着 `metadata.txt` 和 `Miyin/`，让它们跟着铺出去没有意义。

## 3. 版本协商

- 只有声明了 `overrides` 的包才需要 `miyin.format = 2`；其它包继续写 1。
- 老启动器（`MIYIN_FORMAT_VERSION = 1`）见到 `format: 2` 会**明确拒绝**
  （`package.rs`：*该包使用了更新的扩展格式…*），而不是照旧算落点、装到错地方。
  这正是 v2 §0 目标 3 想要的行为。
- **txt 形式没有这层保护**：JSON 才有 `miyin.format`，`metadata.txt` 里的键老启动器一律当
  "不认识的键"忽略。所以：

  | 包 | 老启动器会怎样 |
  | --- | --- |
  | JSON + `format: 2` | 明确拒绝（正确） |
  | txt + `overrides=` | 按老规则装：镜像路径碰巧落对，其它文件悄悄丢掉 —— **半残** |

  所以**包作者优先用 JSON**；txt 只用于纯镜像形态的包（那种情况下老启动器碰巧也能装对）。

## 4. 导出怎么办

导出的包**默认仍是 CCM 形态**（根 `metadata.txt` + 平铺地图/模组 + `Miyin/`）。
带覆盖规则时：

```text
复刻战役.zip
├── metadata.txt            # CCM 读这个
├── paiur01.SC2Map          # 平铺的地图（老工具能看见的那部分）
├── Miyin/
│   ├── metadata.json       # 完整数据，含 miyin.overrides
│   └── overrides/…         # 覆盖内容放这里，不放在包根
└── …
```

覆盖内容放 `Miyin/` 里而不是包根，是为了让 CCM 之类**看不见它** ——
放在根上它们会把这些地图也扫一遍，同一张地图装两遍。

CCM 读不了 `overrides`，所以它只会看到平铺的那部分（能玩，但不完整）。
这一条要在导出界面上**如实说明**，别让作者以为导出的包到哪都一样。

## 5. 实现接在哪（给将来的自己）

| 步骤 | 位置 |
| --- | --- |
| 解析规则 | `campaign/metadata.rs`：JSON 的 `miyin.overrides` + txt 的 `overrides=` |
| 决定落点 | `campaign/package.rs` 的 `payload_target()`：**先问规则**，命中就不走旧推断 |
| 合成 | `library/compose.rs`：被规则命中的载荷不再经过 `Placement` |
| 非载荷文件 | `Payload` 现在只认 `.SC2Map`/`.SC2Mod`，v3 需要一类 `PayloadTarget::Overlay`，来源是规则目录里的**任意**文件 |
| 落点校验 | 不再限制落点，改成**写前快照 + 可完全还原**（`developer-workflow.md` §2） |
| 记账与回滚 | 用现成的 `Manifest`，`deactivate` 精确回滚 —— **这套不改** |

- [ ] `miyin.format = 2` 之后，导出的包默认写几？（写 2 会让只支持 1 的老版本拒绝，
      即使这个包根本没用 overrides）

## 7. 与 issue #17 的关系

#17 里那张 `mount` 表**就是这个 `overrides`**。"覆盖文件夹"这个词是包作者从
CurseForge 就认识的，所以名字跟着它走，不再另造一个 `mount`。
